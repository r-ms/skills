## 1. Advanced Jobs To Be Done (AJTBD)

*Источник: Иван Замесин*

### 1.1. Граф работ (Job Graph)

Пользователь движется по иерархии задач:

- **Высокоуровневая работа** — смысл ("стать здоровым", "успеть всё", "почувствовать контроль").
- **Основная работа** — конкретная задача в продукте ("записаться к врачу").
- **Микро-работы** — действия, которые нужны интерфейсу ("ввести пароль", "скролл").

**Анализ:**

1. Определи высшую работу.
2. Определи основную.
3. Выпиши микро-работы.
4. Проверяй: нужна ли каждая? можно ли убрать/автоматизировать?

### 1.2. Механики создания ценности

Продукт создаёт ценность, когда снижает энергию выполнения работы.

Методы:

- **Kill a job** — убрать шаг (пример: Apple Pay).
- **Fix problems** — устранить трение и несоответствия.
- **Reduce latency** — ускорить отклик.
- **Do more jobs** — объединить две работы в одну.
- **Go meta / превентивные решения** — помочь ещё до возникновения проблемы.

**Анализ:**

- Что можно убить?
- Где задержки?
- Какие шаги объединяем?

### 1.3. Налоговые работы (Tax Jobs)

Плохой UX → пользователь делает ненужную работу:

- логин
- настройки
- поиск нужной функции
- заполнение форм
- подтверждения
- фильтры, которые нужны системе

**Правило:**
Если налоговые работы занимают >20% экрана или времени → критическая ошибка.

### 1.4. Ошибка Предсказания (Prediction Error)

Проблема возникает, когда ожидание пользователя ≠ результату.

Типичные проявления:

- кнопка выглядит активной, но не работает
- ничего не происходит после действия
- пустые экраны
- неожиданные переходы

**Анализ:**
Каждый элемент → какую гипотезу формирует? Реальность ей соответствует?

## 2. Эвристики юзабилити Нильсена

### 1. Видимость статуса системы

- система сообщает, что происходит: загрузка, успех, ошибка
- активные элементы визуально активны

### 2. Сходство с реальным миром

- говорить на языке пользователя
- использовать знакомые метафоры

### 3. Контроль и свобода

- undo
- cancel
- закрытие модалок
- выход из ошибочного состояния

### 4. Единообразие и стандарты

- одинаковые названия одинаковых действий
- одинаковые паттерны расположения кнопок

### 5. Предотвращение ошибок

- подтверждения опасных действий
- валидация ввода
- разделение безопасных и опасных кнопок

### 6. Узнавание вместо вспоминания

- пункты меню видны сразу
- показывать историю, контекст, подсказки

### 7. Гибкость и эффективность

- горячие клавиши
- быстрые действия
- пресеты

### 8. Минимализм

- отсутствие визуального шума
- только важная информация
- понятная иерархия

### 9. Помощь с ошибками

- человеческий язык
- указание источника ошибки
- путь к исправлению

### 10. Помощь и документация

- контекстные подсказки
- FAQ
- гайд в 1 клик от проблемного места

## 3. Когнитивные UX-законы

### 3.1. Закон Фиттса

Время попадания в цель зависит от расстояния и размера.
→ CTA должен быть большим и рядом.

### 3.2. Закон Хика

До 5–7 опций в блоке.
Чем сложнее выбор — тем дольше решение.
→ разбиение на шаги.

### 3.3. Пропасти Нормана

- **Execution gulf:** "я хочу, но где это?".
- **Evaluation gulf:** "я сделал, но что произошло?".

### 3.4. Ментальные модели

Пользователь сравнивает с опытом других продуктов.
→ Следовать стандартам индустрии.

## 4. UX-антипаттерны

### 4.1. Dark Patterns

- скрытые подписки
- обманные CTA
- визуальная манипуляция

### 4.2. False Affordances

Элементы выглядят кликабельными, но не кликабельны.

### 4.3. Progress Blockers

Интерфейс требует действия, не связанного с задачей.

### 4.4. Modal Hell

Слишком много всплывающих окон.

### 4.5. Empty State Failures

Пустой экран без инструкции.

### 4.6. Over-Onboarding

Слишком много шагов, прежде чем дать ценность.

## 5. UX-паттерны (Best Practices)

### 5.1. Паттерны поиска

- поиск + фильтры
- рекомендации
- подсказки по запросу
- история запросов

### 5.2. Паттерны карточек

- визуальная иерархия
- click area на всю карточку
- важная инфа сверху

### 5.3. Паттерны списков

- бесконечный скролл или пагинация
- sticky header
- skeleton loading

### 5.4. Паттерны фильтров

- простые категории
- понятные бейджи "фильтр активен"
- быстрый сброс

### 5.5. Паттерны форм

- один экран = одна задача
- inline validation
- автозаполнение

### 5.6. Паттерны навигации

- табы
- нижнее меню
- хлебные крошки

### 5.7. Паттерны таблиц

- сортировка
- bulk actions
- контекстные действия

## 6. UX-метрики и бизнес-метрики

### 6.1. UX-метрики

- Время до выполнения задачи
- Количество шагов
- Количество ошибок
- Drop-off на каждом шаге
- Количество микро-работ
- Латентность отклика

### 6.2. Бизнес + продуктовые метрики

- Activation Rate
- Retention
- Conversion
- Time-to-Value (TTV)
- North Star Metric

## 7. Product Thinking Layer

Основные концепции:

- Ценность = выполнение работы с меньшей энергией
- Hypothesis → Impact → Effort
- Цепочки JTBD
- Outcome statements
- Решения → Механизмы → Эффекты → Метрики

## 8. AI-UX: паттерны для интерфейсов с ИИ

### 8.1. Объяснимость (Explainability)

Показывать: откуда ответ, почему так.

### 8.2. Patience UI

UI ожидания: анимации, прогресс, этапы генерации.

### 8.3. Correction Loops

Обратная связь от пользователя для уточнения результата.

### 8.4. Prompt affordances

- примеры запросов
- подсказки
- автодополнение

### 8.5. Версионирование

Каждая генерация сохраняется как версия.

## 9. Mobile UX: правила и ограничения

- Touch-target ≥ 44px
- Основные действия — в зоне большого пальца
- Bottom sheets вместо fullscreen
- Swipe actions
- Быстрое закрытие жестами

## 10. UX Writing

### Принципы:

- Четкость
- Краткость
- Контекст
- Действие + результат
- Позитивный тон
- Человек, а не система

### Структуры:

- Кнопки: **Глагол + объект**
- Ошибки: **Что случилось → почему → что делать**
- Онбординг: **1 экран = 1 смысл**
