# Knowledge Base: Strategy + AJTBD

## 1. Ключевые принципы стратегического мышления

**Мышление "От AS IS к TO BE"**: Стратегия — проработанный маршрут перехода от текущей бизнес-модели (AS IS) к целевой (TO BE). Переход должен быть обоснован через анализ ограничений роста.

**Фокус на Юнит-экономике**: Любая стратегическая инициатива должна быть просчитана через пирамиду метрик. Ключевые показатели: LTV, CAC, Retention Rate, ARPU.

**Гипотезо-ориентированный подход**: Рост компании строится на проверке гипотез. Бэклог идей должен проходить скоринг (оценку) и превращаться в эксперименты с понятными метриками успеха.

**Диверсификация рисков (SWOT + Тренды)**: Стратегия должна учитывать макротренды (например, развитие ИИ, изменения в SEO, регуляторные риски) и предлагать способы минимизации угроз через сильные стороны компании.

**Сегментация и Ценностное предложение**: Нельзя делать продукт "для всех". Необходимо четкое разделение аудитории и формирование уникального Value Proposition для каждого сегмента.

**Удержание (Retention) как новый драйвер роста**: В условиях насыщения рынка фокус смещается с привлечения (Acquisition) на удержание, создание комьюнити, геймификацию и работу с базой (CRM).

## 2. Алгоритм разработки стратегии (5-шаговый процесс)

### Модуль 1: Аудит и Диагностика (Понимание "AS IS")

- Схематизация текущей бизнес-модели: Описать, как компания зарабатывает сейчас (Business Model Canvas).
- Целеполагание: Формализация целей бизнеса по SMART.
- SWOT-анализ: Выявление сильных/слабых сторон, возможностей и угроз.
- Профилирование потребителя: Кто наш клиент? (Lean Canvas, Value Proposition Canvas).
- Формализация продукта: Определение North Star Metric (NSM) и ключевой ценности.
- Анализ экономики: Пирамида метрик текущего продукта.

### Модуль 2: Анализ Рынка и Среды (Внешний контур)

- Макросреда и Тренды: PESTEL-анализ, изучение технологических (AI) и социальных трендов.
- Конкурентный анализ: Прямые, косвенные конкуренты и "вытеснители". Сравнение бизнес-моделей.
- Оценка объема рынка: Расчет TAM, SAM, SOM.
- Верификация рисков: Оценка рисков для текущей модели.
- Генерация идей роста: Создание бэклога идей на стыке SWOT и трендов, первичный скоринг.

### Модуль 3: Редизайн Бизнес-модели (Проектирование "TO BE")

- Проблематизация: Выявление ключевого ограничения роста (почему нельзя вырасти в текущей модели?).
- Сценарное планирование: Разработка нескольких стратегических сценариев.
- Динамическая стратегия: Описание перехода от статической модели к динамической.
- Проектирование новой БМ: Создание Canvas будущей модели.

### Модуль 4: Дорожная карта (Roadmap) и Внедрение

- Жизненный цикл продукта: Определение этапа (MVP, PMF, Scale).
- Плановая экономика: Прогноз метрик для новой модели.
- Value Stream Mapping: Распределение ценностных предложений по этапам roadmap.
- Работа с гипотезами: Превращение roadmap в набор гипотез (PRD).
- Схема перехода: Визуализация шагов трансформации.

### Модуль 5: Операционная модель и Лидерство

- Архитектура команд: Оргструктура под новую стратегию (Create, Run, Change команды).
- Целеполагание для команд: Каскадирование целей (OKR/KPI) от стратегии к командам.
- Процессы управления: Ритм встреч, артефакты, зоны ответственности.
- Развитие компетенций: Карта навыков (Skill map) для реализации новой стратегии.

## 3. Инструментарий и Фреймворки

- **Business Model Canvas / Lean Canvas**: Для описания бизнес-модели.
- **Value Proposition Canvas**: Для синхронизации болей клиента и решений продукта.
- **North Star Metric (NSM)**: Ключевая метрика ценности.
- **Пирамида метрик**: Связь финансовых целей с продуктовыми метриками.
- **TAM/SAM/SOM/PAM**: Для оценки рынка.
- **SWOT + PESTEL**: Для стратегического анализа.
- **5 Сил Портера**: Для анализа конкуренции.
- **CJM (Customer Journey Map)**: Для анализа пути пользователя.
- **OKR (Objectives and Key Results)**: Для постановки целей.

## 4. Принципы Advanced JTBD

### Фундаментальные аксиомы

**Работа важнее продукта.** Людям нужно выполнить их «Работу» (Job) — достичь цели, удовлетворить потребность и перейти из точки А в точку Б.

**Работа первична, решение заменяемо.** Продукт — это «решение», которое «нанимают» на работу. Мы конкурируем за право быть нанятым на выполнение работы.

**Ценность = Энергоэффективность.** Ценность продукта — это возможность выполнить работу с меньшими затратами энергии, времени, денег и нервов. Мозг — инвестор, он вкладывает ресурсы, чтобы получить больше ресурсов.

**Проблема — это ошибка предсказания.** «Боль» возникает, когда текущее решение потратило больше ресурсов или дало меньше пользы, чем ожидал мозг.

### Единица анализа: Граф работ (Job Graph)

Рассматривай работу как Граф работ — иерархию задач:

- **Высокоуровневая работа**: Глобальная цель (например, «Быть здоровым и красивым»).
- **Работа (Job)**: Конкретная задача (например, «Начать бегать по утрам»).
- **Низкоуровневые работы (Micro-jobs)**: Шаги процесса (встать, найти кроссовки, выбрать маршрут).
- **Критическая последовательность**: Шаги, которые нельзя пропустить.

### Механики создания ценности

**Убийство работ (Job Killing)**: Как убрать шаги из графа? Самая мощная механика. «Упрощение» — это всегда убийство низкоуровневых работ. Пример: такси в приложении убило работу «звонить диспетчеру и объяснять, где я».

**Выход на Предыдущую работу (Previous Job)**: Перехватить клиента до того, как он начал искать основное решение. Пример: Aviasales помогает найти билеты.

**Выход на Высокоуровневую работу (Higher Level Job)**: Вместо инструмента продать результат «под ключ». Пример: вместо курсов по личному бренду (инструмент) — агентство делает всё за клиента (результат).

**Выполнение нескольких работ одним решением**: Объединение контекстов. Пример: заправка + кофе + магазин.

**Смещение в денежный сегмент**: Искать тех, у кого есть бюджет и высокая мотивация.

**Починка проблем**: Исправление «багов» текущих решений (устранение негативных эмоций и налоговых работ).

### Работа с Привычками (Habits)

Мозг ленив. Привычка экономит энергию. Менять привычку — это «дорого» для мозга.

**Принцип**: Переиспользуй старые привычки. Пример: Яндекс Музыка при переезде из Spotify импортировала лайки.

**Редизайн опасен**: Если меняешь интерфейс, делай это атомарно, чтобы не сломать нейронные связи пользователя.

**Создание новой привычки**: Только если продукт дает кардинально больше ценности (в 10 раз лучше).

## 5. Теоретическая база

### Бизнес-моделирование (А. Остервальдер)

**Принцип целостности системы**: Бизнес-модель — это система взаимосвязей. Изменение одного блока требует изменений в других.

**Три уровня Fit**:
- Problem-Solution Fit: Есть доказательства, что клиентам важно решение определенных задач.
- Product-Market Fit: Продукты создают ценность и находят отклик на рынке.
- Business Model Fit: Это можно масштабировать и сделать прибыльным.

### Юнит-экономика (И. Красинский)

**Принцип масштабирования**: Масштабируем прибыльную бизнес-модель. Сначала свести экономику на одном юните.

**Поиск узкого горлышка**: В любой системе есть одно главное ограничение. Улучшения вне узкого горлышка — иллюзия деятельности.

**Когортный анализ**: Средние метрики врут. Анализировать нужно по когортам.

**Маржинальность — главная метрика**: Фокус на Contribution Margin. Если CM отрицательная, рост убивает компанию.

### Стратегии Роста (Reforge, Б. Балфур)

**Retention is King**: Если плохой Retention — привлекать новых бессмысленно («дырявое ведро»).

**Петли роста (Growth Loops) > Воронки**: Воронки линейны. Петли цикличны: действия одного пользователя приводят к появлению следующего.

**Закон Четырех Соответствий**:
- Market-Product Fit
- Product-Channel Fit
- Channel-Model Fit
- Model-Market Fit

### Жизненный цикл (Дж. Мур)

**Пропасть (The Chasm)**: Между Ранними последователями и Ранним большинством лежит пропасть.

**Стратегия Кегельбана**: Чтобы преодолеть пропасть — выбрать узкую нишу, доминировать в ней, потом расширяться.

### Продуктовая культура (М. Каган)

**Миссионеры против Наемников**:
- Наемники: Строят то, что сказали (output).
- Миссионеры: Решают проблемы (outcome).

**Dual Track Agile**: Разработка параллельно с исследованием (Discovery).

**Когнитивная нагрузка**: Структура команд должна снижать когнитивную нагрузку.

### Психология пользователя (Н. Эяль, модель Hooked)

**Модель Крючка**: Trigger -> Action -> Reward -> Investment

- **Триггер**: Что побуждает зайти?
- **Действие**: Должно быть максимально простым.
- **Переменная награда**: Предсказуемость убивает интерес.
- **Инвестиция**: Пользователь должен вложить что-то, чтобы было жалко уйти.

### Силы Прогресса (Bob Moesta)

Анализируй переключение пользователя через 4 силы:
- **Push (Толчок)**: Проблемы с текущим решением.
- **Pull (Тяга)**: Привлекательность нового решения.
- **Anxiety (Тревога)**: Страх неопределенности нового.
- **Habit (Привычка)**: Инерция старого.

### Нейробиология (Л. Фельдман Барретт)

**Аллостаз**: Мозг как финансовый директор, управляющий бюджетом тела. Любое действие — инвестиция. Продукт должен давать ROI выше затрат.

### Поведенческий дизайн (BJ Fogg)

**Формула B = MAP**: Behavior = Motivation + Ability + Prompt

Увеличить ценность — это чаще всего увеличить Ability (сделать действие простым).

### Стратегия голубого океана

**Сетка ERRC**:
- Eliminate (Упразднить) = Убийство работ
- Raise (Повысить) = Улучшение ключевой работы
- Reduce (Снизить) = Снижение костов
- Create (Создать) = Новая ценность

### OODA-цикл (Дж. Бойд)

Наблюдай (Observe) -> Ориентируйся (Orient) -> Решай (Decide) -> Действуй (Act)

Скорость итераций важнее качества первого плана.

### Сегментация

- Сегментируй по Работам и по связке Работа + Текущее Решение.
- Ищи сегменты, где решение "облажалось" сильнее всего или где самая высокая маржинальность.
